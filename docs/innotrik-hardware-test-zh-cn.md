# INNOTRIK BLE 硬件测试指南（Android 测试版）

## 1. 本版本可以测试什么

- 扫描并选择附近的蓝牙设备；
- 检查设备是否包含 INNOTRIK 协议服务 `FF12 / FF13 / FF14`；
- 发送开始录音命令 `55 AA A5 59` 和停止命令 `55 AA A5 58`；
- 接收并重新组装 84 字节音频包；
- 提取 80 字节 Raw Opus，使用 Android 原生解码器转为 PCM16 24 kHz；
- 显示有效包数、错误包数和已解码 PCM 数据量；
- 录音 4 秒并立即回放，用于确认麦克风、Opus 参数和播放速度；
- 连接成功后启用 BLE 流式识别，并保留 Realtime → Batch Chunks 备用流程。

## 2. 安装前准备

1. 使用真实 Android 手机；Android 模拟器不能验证 BLE 麦克风。
2. 打开手机蓝牙，并给应用“附近设备/蓝牙”权限。
3. 打开 INNOTRIK 设备，放在手机 0.5–1 米范围内。
4. 测试时先不要连接厂商原 App，避免两个 App 同时占用 GATT。

## 3. 推荐测试顺序

1. 安装并打开 APK。
2. 打开右上角“设置”。
3. 如需中文界面，将“显示语言”切换为“简体中文”。
4. 在“INNOTRIK 麦克风”卡片点击“扫描连接”。
5. 优先选择带绿色认证标记的设备；该标记表示设备名称或广播服务与 INNOTRIK 相符。
6. 等待状态显示：
   - “已连接”；
   - “Opus 解码器就绪”；
   - “24 kHz PCM”。
7. 点击“测试麦克风 4 秒”，在设备麦克风附近说一句话。
8. 测试成功后，页面应显示音频包数量和 PCM KB，并自动回放刚才的录音。
9. 如果回放声音正常，再返回主页点击“开始说话”，测试完整识别、翻译和 TTS 流程。

## 4. 如何判断结果

| 现象 | 判断 | 需要提供的信息 |
|---|---|---|
| 找不到设备 | 蓝牙权限、设备电源或广播有问题 | 手机型号、Android 版本、设备蓝牙名称 |
| 能找到但提示没有 FF12/FF13/FF14 | 选错设备或固件协议不同 | 设备名称、固件版本、错误截图 |
| 已连接，但有效包数为 0 | 启动命令未被接受，或设备需要额外认证 | 状态截图、厂商 App 是否能录音 |
| 有效包数增加，但 PCM 为 0 | Raw Opus 参数与当前 Android 解码配置不匹配 | 包数、错误信息、设备固件版本 |
| 可以回放但声音过快/过慢 | 实际采样率或 Opus 帧时长需要调整 | 4 秒录音的实际回放时长 |
| 录音中断线 | GATT 信号或固件稳定性问题 | 距离、断线时间、是否自动重连 |
| 4 秒测试成功，但主页识别失败 | BLE 已正常，问题在网络或 backend | backend 地址、HTTP 状态、网络环境 |

## 5. Backend 说明

“测试麦克风 4 秒”不需要公网 backend，可以独立验证 BLE、Opus 解码和本地回放。

本次交付的 `real-backend` APK 已关闭 Demo 模式，并连接以下正式 HTTPS backend：

`https://speaking-ai-nextjs-backend-production.up.railway.app`

主页可以测试完整的“越南语语音 → 英语文本/语音”流程。测试手机必须可以正常访问互联网；如果 4 秒麦克风测试成功、但主页识别失败，请同时检查中国网络到上述域名的访问情况。API 密钥只保存在 backend 中，不包含在 APK 内。

## 6. 验收最低标准

- 连续收到至少 100 个有效 84 字节包；
- 错误包数量接近 0；
- 4 秒录音可以正常回放，速度和音调自然；
- 开始、停止命令每次都有效；
- 断开后可重新连接；
- 完整流程中页面明确显示使用的是 `Mic INNOTRIK`，不能误用手机麦克风。
